# UI·UX 원칙

<aside>
🖥️

CEX UI·UX의 최우선 목표는 플레이어가 입력 결과와 적의 다음 행동을 즉시 읽을 수 있게 하는 것입니다.

</aside>

## 입력 피드백

- 커맨드 성공 직후 스킬이 실제로 시작되었다는 사실을 즉시 알려야 한다.
- 시각 효과, 사운드, 캐릭터·장비 모션, 상태 변화 중 최소 하나 이상을 사용한다.
- 후딜이 존재하는 스킬은 입력 성공 후 타격까지의 상태를 계속 보여준다.
- 실패 입력과 성공 입력의 피드백은 명확히 구분한다.

## 적 공격 예고

- 적 공격의 선딜은 **가로 진행 게이지**로 표시한다.
- 게이지 충전 동안 공격별 준비 모션을 함께 보여 공격 종류를 판별할 수 있게 한다.
- 게이지가 가득 차면 시전 완료로 전환한다.
- 후딜이 있는 공격은 투사체, 이펙트 또는 별도 상태로 타격 시점까지 추적 가능해야 한다.
- 이전 공격의 후딜과 다음 공격의 선딜이 겹칠 수 있으므로 두 상태를 동시에 읽을 수 있어야 한다.

## 타이포그래피

- 본문과 일반 UI 텍스트는 **갈무리9(Galmuri9)**를 우선 사용한다.
- 제목은 각진 판타지 계열 서체를 사용할 수 있다.
- 커맨드는 한글 획 구분과 입력 판독성이 가장 우선이다.
- 전투 중 긴 설명보다 짧고 반복 가능한 시각 언어를 사용한다.

## Mood · Visual Direction

<aside>
🎨

UI는 단순히 판타지 장식을 얹는 것이 아니라, **금지된 마법 문서를 읽으며 탑을 공략하는 전투 인터페이스**처럼 느껴져야 한다. 단, 분위기보다 전투 정보의 판독성이 항상 우선한다.

</aside>

### 핵심 무드

- 기본 방향은 **어두운 판타지 × 마법 문서 × 탑 탐험**이다.
- 음울하고 기묘한 긴장감은 유지하되, 화면 전체를 탁하고 무겁게 만들어 정보를 숨기지 않는다.
- 현대적인 SaaS 대시보드보다 **낡은 마도서, 석판, 봉인 문서, 기록 장치**에 가까운 인상을 우선한다.
- 화려함은 상시 노출하지 않고 **입력 성공, 공격 시전, 희귀 보상, 보스의 핵심 기믹**처럼 의미가 있는 순간에 집중한다.

### 시각 언어

- **배경**: 저채도·저명도의 어두운 기반을 사용해 전투 정보와 캐릭터 실루엣이 앞으로 나오게 한다.
- **재질**: 돌, 잉크, 오래된 종이, 금속 장식, 마법 각인처럼 세계관에 속한 재질을 우선한다. 텍스처는 읽기를 방해하지 않는 범위에서만 사용한다.
- **형태**: 제목, 프레임, 장식에는 각지고 판타지적인 실루엣을 사용할 수 있지만, HP·게이지·커맨드·상태 정보는 단순하고 즉시 구분 가능한 형태를 유지한다.
- **색**: 색은 장식보다 상태 전달에 먼저 사용한다. 위험, 입력 성공, 시전 중, 희귀도 같은 의미를 가진 강조색은 서로 역할이 겹치지 않게 한다.
- **빛과 이펙트**: 글로우, 파티클, 화면 흔들림은 핵심 순간에 짧게 사용한다. 상시 발광이나 과도한 파티클로 커맨드와 공격 예고를 가리지 않는다.
- **아이콘**: 가능한 경우 문양, 인장, 룬, 무기·유물 실루엣처럼 세계관 안에서 설명되는 형태를 사용한다. 의미가 불명확한 장식 아이콘은 추가하지 않는다.

### 화면별 무드 강도

- **전투 화면**: 가장 절제한다. 판독성, 타이밍, 대상 구분이 최우선이며 장식은 전투 정보를 둘러싸는 수준에 머문다.
- **장비·유물·보상 화면**: 전투보다 장식 밀도를 높여 **유물을 감정하거나 마법 문서를 펼쳐보는 경험**을 강화할 수 있다.
- **탑·스테이지 선택 화면**: 깊이, 미지의 공간, 상승 또는 탐험의 감각을 강조한다. 다음 구간에 대한 기대와 위험을 동시에 보여준다.
- **보스 연출**: 평상시보다 대비, 타이포그래피, 문양, 이펙트의 강도를 올릴 수 있지만 실제 패턴 판독이 시작되면 다시 전투 정보가 우선한다.

### 피해야 할 방향

- 일반적인 웹앱처럼 보이는 **glassmorphism, 동일한 둥근 카드의 반복, 과도하게 깨끗한 SaaS형 레이아웃**을 기본 문법으로 사용하지 않는다.
- 모든 테두리와 패널을 복잡한 판타지 장식으로 채우지 않는다.
- 어두운 판타지를 이유로 텍스트 대비를 낮추거나 화면 전체를 갈색·회색 한 톤으로 뭉개지 않는다.
- 모든 중요 상태를 네온 글로우나 색상 하나만으로 표현하지 않는다.
- 장식 목적의 애니메이션이 입력 피드백이나 적 공격 예고보다 더 강하게 보이지 않게 한다.

### 아직 고정하지 않는 것

- 정확한 전역 컬러 팔레트와 HEX 값
- 패널 모서리와 테두리의 최종 스타일
- 픽셀 단위의 spacing·radius 토큰
- 아이콘 세트와 이펙트 스타일의 최종 에셋 규격

위 항목은 실제 화면 시안과 플레이테스트를 통해 디자인 토큰으로 승격한다.

## AI / UI 작업 시 참조 규칙

UI를 구현하거나 수정하는 Agent는 다음 순서로 판단한다.

1. 먼저 **플레이어가 지금 읽어야 하는 정보와 행동**을 정의한다.
2. 레이아웃과 정보 위계를 먼저 해결한 뒤 Mood를 적용한다.
3. 시각 선택은 **어두운 판타지 × 마법 문서 × 탑 탐험** 중 어느 축을 강화하는지 설명 가능해야 한다.
4. 기존 UI와 다른 새로운 색, 프레임, 효과 문법을 도입할 때는 전역 스타일로 바로 확정하지 말고 재사용 가능성을 확인한다.
5. UI 변경 후 커맨드, HP, 적 공격 예고, 대상, 상태 이상이 장식보다 먼저 읽히는지 검토한다.
6. 애매한 미적 판단은 임의로 한 가지를 영구 고정하기보다 2~3개의 시안 또는 구현 가능한 변형으로 비교할 수 있게 남긴다.
7. 구현 결과를 스크린샷으로 검토할 때는 **판독성 → 정보 위계 → 무드 일관성 → 장식 완성도** 순서로 평가한다.

## 접근성

- 글자 크기 조절을 지원하는 방향을 유지한다.
- 공격 정보를 색상 하나에만 의존하지 않고 게이지, 모션, 텍스트 또는 아이콘을 병행한다.
- 사운드를 끈 상태에서도 입력 성공과 공격 타이밍을 판단할 수 있어야 한다.

## 원칙

- **판독 가능하면 어렵게, 판독 불가능하게 어렵게 만들지 않는다.**
- 피격 원인을 플레이어가 설명할 수 있어야 한다.
- 입력 성공 이후 결과가 늦게 발생하더라도 시스템이 반응하지 않은 것처럼 보이면 안 된다.

## 미정 사항

- 커맨드 입력창의 정확한 위치
- 선딜 게이지 색상·크기·배치
- 후딜 표시 방식
- 접근성 옵션의 초기 출시 범위
