# UI/UX Principles: Mood & Visual Direction

이 문서는 `apps/game`의 UI 작업자가 화면의 시각적 방향과 판단 기준을 일관되게 적용하기 위한 문서입니다. 기능 요구사항과 현재 디자인 구현을 대체하지 않으며, UI를 구현하거나 리뷰할 때 함께 참조합니다.

## Core mood

프로젝트의 기본 무드는 다음 세 요소의 결합입니다.

`dark fantasy × magical documents × tower exploration`

- **Dark fantasy**: 어둡고 깊이 있는 값과 제한된 빛으로 위험과 긴장감을 표현합니다.
- **Magical documents**: 기록지, 지도, 주석, 봉인, 문양처럼 세계 안에 존재하는 문서의 질감을 사용합니다.
- **Tower exploration**: 층을 오르고 경로를 선택하는 감각이 화면 구조와 진행 표현에 드러나게 합니다.

세 요소는 장식을 추가하는 기준으로 사용합니다. 게임플레이 정보를 가리거나 조작을 어렵게 만드는 경우 무드 적용을 줄입니다.

## Visual language

시각 요소는 서로 독립적으로 유행하는 스타일을 조합하지 않고, 하나의 게임 세계 안에서 함께 존재하는 언어로 다룹니다.

### Background

- 어두운 탑의 공간감, 낡은 기록물, 깊이를 암시하는 층을 배경의 출발점으로 삼습니다.
- 배경의 질감과 대비는 전경의 텍스트 및 인터랙션을 읽는 데 방해가 되지 않는 수준으로 제한합니다.
- 화면의 주의를 끌어야 하는 요소 뒤에는 장식적인 패턴이나 효과를 두지 않습니다.

### Material

- 종이, 잉크, 돌, 금속, 봉인과 같은 재질을 문서와 탑의 맥락에 맞게 사용합니다.
- 재질 표현은 컴포넌트의 역할을 설명하는 데 기여해야 하며, 모든 영역을 같은 표면 효과로 채우지 않습니다.

### Shape

- 문서의 영역, 지도, 표식, 탭, 프레임처럼 의미가 있는 형태를 우선합니다.
- 모서리가 둥근 일반 웹 카드와 같은 형태를 반복해 대시보드처럼 보이게 만들지 않습니다.
- 형태의 변형은 정보 그룹과 상호작용을 구분하는 데 사용하고, 장식만을 위해 추가하지 않습니다.

### Color

- 어두운 기반 위에 제한된 강조색을 사용해 시선의 우선순위와 상태를 전달합니다.
- 색상은 상태를 전달하는 보조 수단으로 사용하고, 텍스트·아이콘·형태와 함께 의미를 전달합니다.
- 이 문서는 구체적인 HEX 값, 명도 단계, 희귀도 색상 또는 전투 상태 색상을 확정하지 않습니다.

### Light

- 빛과 발광은 현재 집중해야 하는 대상, 중요한 상태 변화, 보상 또는 위험의 방향을 강조하는 데 사용합니다.
- 전체 화면을 균일한 글로우나 그라디언트로 덮어 정보 대비를 약화하지 않습니다.

### Icon

- 아이콘은 문서의 기호, 도구, 표식처럼 세계관과 기능을 동시에 설명해야 합니다.
- 아이콘만으로 핵심 상태를 전달하지 않고, 필요한 경우 짧은 텍스트와 수치를 함께 제공합니다.
- 아이콘의 실루엣과 의미가 화면마다 달라지지 않도록 기존 아이콘 체계와 맥락을 먼저 확인합니다.

### Typography

- 제목, 설명, 수치, 명령어의 역할을 명확히 구분하고, 플레이 중 반복해서 읽는 정보는 장식보다 판독성을 우선합니다.
- 명령어, HP/AP, 적 공격 예고, 상태 효과, 대상 정보에는 장식적인 서체나 과한 효과를 적용하지 않습니다.
- 제목과 세계관 텍스트에 표현을 사용할 수 있지만, 작은 텍스트와 긴 문장의 읽기 흐름을 해치지 않아야 합니다.
- 구체적인 폰트 크기와 행간 단계는 실제 화면에서 반복 패턴을 확인한 뒤 토큰으로 정리합니다.

### Framing

- 프레임, 모서리 표시, 탭, 봉인, 주석선은 정보의 소속과 진행 맥락을 설명할 때 사용합니다.
- 프레임은 콘텐츠의 경계와 상호작용 상태를 명확히 해야 하며, 텍스트·수치·버튼 위에 겹치지 않습니다.
- 모든 정보를 카드 안에 넣는 방식은 피하고, 화면의 문서·지도·전투 맥락에 맞는 배치를 선택합니다.

## Screen direction

화면마다 같은 장식 강도를 적용하지 않습니다. 화면의 목적과 플레이어가 즉시 확인해야 하는 정보를 기준으로 무드의 강도와 표현을 조절합니다.

### Combat

전투 화면은 입력과 전투 상태의 판독성이 가장 우선입니다. 다음 정보가 장식보다 먼저 읽혀야 합니다.

- commands와 현재 입력 대상
- HP/AP와 변경 상태
- enemy intent 및 공격 예고
- status effects
- 현재 target

배경, 재질, 빛, 전투 효과는 위 정보를 강조하는 범위에서 사용합니다. 적의 의도와 대상이 장식 또는 애니메이션에 묻히지 않게 합니다.

### Reward

보상 화면은 무엇을 얻는지, 희귀도와 효과가 무엇인지, 어떤 선택을 해야 하는지가 분명해야 합니다. 보상에 시선을 모으는 재질과 빛을 사용할 수 있지만, 보상 설명과 선택 동작을 장식으로 분리하지 않습니다.

### Tower selection

탑 선택 화면은 현재 층, 선택 가능한 경로, 각 경로의 성격과 위험을 이해할 수 있어야 합니다. 경로와 층의 관계가 지도나 문서 구조로 보이도록 구성하고, 장식적인 수직성 때문에 선택 가능한 대상이 불명확해지지 않게 합니다.

### Boss

보스 화면은 일반 전투와 구분되는 존재감과 위험을 전달합니다. 보스의 상태, enemy intent, 공격 예고, target, 플레이어의 HP/AP와 commands는 강한 연출 중에도 즉시 확인할 수 있어야 합니다. 보스 전용 장식과 효과는 정보 위계를 보조하는 방향으로 제한합니다.

## Readability guardrails

모든 화면에서 다음 정보를 보호합니다.

- 입력해야 하는 commands와 입력 결과
- 플레이어와 적의 HP/AP
- enemy intent와 공격 예고
- status effects와 지속 상태
- 현재 target과 선택 가능한 대상

텍스트와 수치의 대비, 상태의 구분, 클릭 또는 입력 가능한 영역의 경계를 먼저 확인합니다. 배경, 프레임, 파티클, 발광, 장식용 아이콘이 이 정보를 가리거나 비슷하게 보이게 만들면 시각 효과를 줄이거나 위치를 조정합니다.

## Anti-patterns

다음 방향은 프로젝트의 시각 언어와 맞지 않거나 판독성을 해칠 위험이 있으므로 피합니다.

- 반복되는 크고 둥근 카드, 대시보드형 섹션, 필(pill) 중심의 SaaS/Web UI
- 정보와 배경을 투명도와 블러로 겹치는 과도한 glassmorphism
- 네온 글로우, 그라디언트, 파티클을 사용해 핵심 정보의 대비를 약화하는 연출
- 판타지 장식을 텍스트, 수치, 명령어, 상태 표시 위에 배치하는 구성
- 화면 목적과 무관한 프레임·봉인·문양을 반복해 상호작용 영역을 흐리는 구성
- 한 화면의 임시 스타일을 전체 제품의 전역 규칙으로 확정하는 선택

## AI / UI implementation reference rules

UI 작업을 시작하는 에이전트는 이 문서와 기존 디자인 구현을 먼저 확인하고 다음 순서로 판단합니다.

1. 플레이어가 현재 화면에서 가장 먼저 읽어야 할 정보와 수행할 행동을 정의합니다.
2. 정보 위계와 레이아웃을 먼저 정리합니다.
3. `dark fantasy × magical documents × tower exploration`의 시각 언어를 레이아웃 위에 적용합니다.
4. 일반적인 SaaS/Web UI처럼 보이는 표현을 피하고, 게임 세계 안에 존재하는 인터페이스로 구성합니다.
5. commands, HP/AP, enemy intent, status effects, target의 판독성을 장식보다 우선합니다.
6. 기존 디자인 시스템과 컴포넌트 관례를 유지하면서 필요한 spacing, hierarchy, typography, framing, feedback, motion을 개선합니다.
7. 구현을 마친 뒤 다음 순서로 실제 화면을 자체 리뷰합니다.

   `readability → information hierarchy → mood consistency → decorative polish`

8. 시각적 판단이 애매하면 임의의 스타일을 전역 규칙으로 확정하지 않습니다. 선택한 방향은 이후 디자인 토큰으로 정리할 수 있도록 컴포넌트와 구조를 분리합니다.

에이전트 작업 요청에는 이 문서의 경로와 위 review order를 포함합니다. 기능 구현이 끝난 뒤에도 실제 화면에서 네 가지 리뷰 단계를 수행하고 필요한 부분을 한 차례 수정합니다.

## Tokenization boundary

현재 문서는 의도와 원칙을 정의합니다. 다음 항목의 구체적인 수치와 값은 여러 화면에서 반복 패턴이 확인된 뒤 별도의 `Visual Design Tokens` 문서 또는 디자인 시스템으로 승격합니다.

- palette와 명도 단계
- spacing과 radius
- typography scale
- rarity color
- combat state color
- VFX 강도와 타이밍

화면이 충분히 구현되기 전에 이 값을 전역 규칙으로 고정하지 않습니다. 반복되는 실제 UI에서 추출한 토큰은 이 문서의 mood와 readability 원칙을 만족해야 합니다.

## Review checklist

- [ ] `dark fantasy × magical documents × tower exploration`이 화면의 맥락과 일치합니다.
- [ ] background, material, shape, color, light, icon, typography, framing이 같은 시각 언어를 사용합니다.
- [ ] combat, reward, tower selection, boss 화면의 목적에 맞게 무드 강도를 조절했습니다.
- [ ] commands, HP/AP, enemy intent, status effects, target이 즉시 읽힙니다.
- [ ] SaaS 카드 반복, 과도한 glassmorphism, 정보 위를 덮는 판타지 장식을 사용하지 않았습니다.
- [ ] `readability → information hierarchy → mood consistency → decorative polish` 순서로 리뷰했습니다.
- [ ] 아직 확정되지 않은 palette, spacing, radius, rarity, combat state, VFX 수치를 임의로 전역 고정하지 않았습니다.
