# MVP 핵심 루프 E2E 시나리오

이 문서는 튜토리얼과 가챠를 제외한 MVP 핵심 루프를 브라우저에서 반복 검증하기 위한 수동 E2E 시나리오다.

## 공통 준비

1. 최신 `main`을 checkout/pull 한다.
2. 프로젝트 의존성을 설치하고 game dev server를 실행한다.
3. 새 브라우저 탭에서 게임을 연다.
4. 이전 런이 남아 있으면 정산을 완료하거나 저장 데이터를 초기화해 새 런을 시작할 수 있는 상태로 만든다.
5. 각 시나리오에서 Scene 전환 버튼은 한 번만 누르고, 별도 항목에서 중복 클릭 차단을 검증한다.

## E2E-01 앱 실행 → 설정 → 로비 → 런 시작 → 맵

### 절차

1. 앱을 새로 연다.
2. Start 화면이 표시되는지 확인한다.
3. `설정`을 열고 지원 설정 하나를 변경한 뒤 적용한다.
4. Start 화면으로 돌아온다.
5. `게임 시작`을 눌러 Lobby로 이동한다.
6. Lobby에서 런 시작 동작을 실행한다.
7. 새 RunState가 생성되고 Map Scene으로 이동하는지 확인한다.

### 기대 결과

- 앱 최초 화면은 Start다.
- 설정 화면을 열고 닫아도 Scene 흐름이 깨지지 않는다.
- Lobby 진입 후 새 런을 시작할 수 있다.
- Map 진입 시 RunState.status는 `active`다.
- Map에는 선택 가능한 노드와 잠긴 노드가 구분되어 보인다.

## E2E-02 일반 전투 승리 → 보상 → 맵 복귀

### 절차

1. Map에서 `available` 일반 전투 노드를 선택한다.
2. Combat Scene 진입 후 해당 노드의 encounter가 로드되는지 확인한다.
3. 적을 모두 처치해 승리한다.
4. 전투 종료 직후 추가 공격 입력과 적 공격 타임라인이 더 진행되지 않는지 확인한다.
5. 보상 화면에서 보상 하나를 선택·확정한다.
6. 장비 보상이라면 inventory/loadout 반영을 확인한다.
7. Map으로 복귀한다.

### 기대 결과

- 선택한 노드는 전투 중 `in_progress`다.
- 승리 결과와 보상은 한 번만 적용된다.
- 보상 확정 후 같은 보상을 다시 확정할 수 없다.
- Map 복귀 시 완료 노드는 `cleared`다.
- 연결된 다음 노드가 `available`로 열린다.
- 획득한 장비·재화·HP 등 RunState 변경은 유지된다.

## E2E-03 상점 노드 → 구매/나가기 → 맵 복귀

### 절차

1. Map에서 `available` 상점 노드를 선택한다.
2. Shop Scene이 열리는지 확인한다.
3. 구매 가능한 상품 하나를 구매한다.
4. 재화 차감과 inventory 추가를 확인한다.
5. 이미 구매한 동일 offer를 다시 구매하려 할 때 중복 적용되지 않는지 확인한다.
6. `상점 나가기`를 실행한다.
7. Map으로 복귀한다.

### 기대 결과

- 구매 성공 시 RunState.runCurrency가 가격만큼 감소한다.
- 구매 장비가 inventory에 한 번만 추가된다.
- 상점 완료 시 노드가 `cleared`가 된다.
- 다음 연결 노드가 `available`로 열린다.

## E2E-04 휴식 노드 → 회복/휴식 → 맵 복귀

### 절차

1. 플레이어 HP가 최대치보다 낮은 상태에서 `available` 휴식 노드에 진입한다.
2. Rest Scene이 열리는지 확인한다.
3. `회복`을 선택한다.
4. HP가 최대 HP를 넘지 않는 범위에서 증가하는지 확인한다.
5. Map으로 복귀한다.

별도 반복에서 `그냥 쉬고 돌아가기`를 선택해 HP 변화 없이 완료 가능한지도 확인한다.

### 기대 결과

- 동일 휴식 결과는 중복 적용되지 않는다.
- 휴식 완료 후 노드가 `cleared`가 된다.
- 다음 연결 노드가 `available`로 열린다.
- 갱신된 HP가 이후 전투까지 유지된다.

## E2E-05 최종 보스 승리 → 클리어 정산 → 로비

### 절차

1. 최종 보스 이전 필수 경로를 완료한다.
2. 최종 보스 노드가 `available`이 되었는지 확인한다.
3. 보스 노드를 선택해 Combat Scene에 진입한다.
4. boss encounter와 boss reward policy가 선택되는지 확인한다.
5. 보스를 처치해 승리한다.
6. 클리어 정산 화면으로 이동한다.
7. 아이템 환전액 + 클리어 보너스의 총 지급액을 확인한다.
8. 정산 확인을 실행한다.
9. Lobby로 복귀한다.

### 기대 결과

- 잠긴 보스는 진입할 수 없다.
- 보스 승리 시 보스 노드는 `cleared`, RunState.status는 `cleared`가 된다.
- 정산은 같은 런에 대해 한 번만 지급된다.
- 영구 재화가 총 지급액만큼 증가한다.
- 정산 확인 후 활성 RunState가 정리된다.
- Lobby에서 갱신된 영구 재화를 확인할 수 있다.
- 새 런을 다시 시작할 수 있다.

## E2E-06 전투 패배 → 사망 정산 → 로비

### 절차

1. 새 런을 시작하고 전투 노드에 진입한다.
2. 플레이어 HP를 0까지 소진해 패배한다.
3. 전투 종료 직후 추가 입력과 타임라인이 멈추는지 확인한다.
4. 사망 정산 화면으로 이동한다.
5. 보유 런 장비 환전액이 표시되는지 확인한다.
6. 클리어 보너스가 포함되지 않는지 확인한다.
7. 정산 확인 후 Lobby로 복귀한다.

### 기대 결과

- 패배 시 RunState.status는 `dead`다.
- 사망 정산은 같은 런에 대해 한 번만 지급된다.
- 활성 RunState와 런 장비가 정리된다.
- Lobby 영구 재화에 사망 정산 지급액이 반영된다.
- 새 런을 다시 시작할 수 있다.

## E2E-07 잠긴 노드 차단

### 절차

1. Map에서 `locked` 상태 노드를 선택하려 한다.
2. 일반 전투·상점·휴식·보스 각각 가능한 경우 반복한다.

### 기대 결과

- Scene이 전환되지 않는다.
- currentNodeId가 변경되지 않는다.
- locked 노드가 `in_progress`로 바뀌지 않는다.
- 재화·HP·inventory 등 RunState가 변경되지 않는다.

## E2E-08 중복 클릭·중복 결과 차단

### 절차

다음 동작을 빠르게 두 번 이상 실행한다.

1. Lobby의 런 시작.
2. Map의 노드 선택.
3. 보상 확정.
4. 상점 동일 상품 구매.
5. 휴식 회복 결과 적용.
6. 정산 확인.

### 기대 결과

- 새 RunState가 두 번 생성되지 않는다.
- 동일 노드 전환이 중복 실행되지 않는다.
- 보상이 두 번 inventory에 들어가지 않는다.
- 구매 재화가 두 번 차감되지 않는다.
- 회복이 두 번 적용되지 않는다.
- 정산 재화가 두 번 지급되지 않는다.

## 완료 판정

아래 경로가 모두 재현되면 CORE-10-01 시나리오 정의를 충족한다.

- Start → Settings → Start → Lobby → Run Start → Map
- Map → Combat → Reward → Map
- Map → Shop → Map
- Map → Rest → Map
- Map → Boss → Clear Settlement → Lobby
- Map → Combat Defeat → Death Settlement → Lobby
- Locked node 차단
- 주요 액션의 중복 클릭/중복 결과 차단

실제 자동 브라우저 실행 및 Scene 간 RunState 연속성 자동 검증은 후속 통합 테스트 Task에서 수행한다.
